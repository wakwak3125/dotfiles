# deep-loop

夜間の長時間の作業を、brief（依頼の文面）を固めて runner に渡すところから、成果物を読んで伝えるところまで受け持つ。
ラウンドを回す本体は、runner が起こす `claude -p` の中の `deep-loop:run` skill と Workflow が持つ。

runner は `PLUGIN/scripts/deep-loop` にある。`PLUGIN` は、このスキルの base directory の 2 つ上である。

```bash
PLUGIN/scripts/deep-loop start <名前> [--repo <絶対パス>]... [--rounds <1-3>] [--at <HH:MM>] [--model <役>=<model>]... [--effort <役>=<effort>]... < brief.md
PLUGIN/scripts/deep-loop status [<名前>]
PLUGIN/scripts/deep-loop report <名前>
PLUGIN/scripts/deep-loop resume <名前>
PLUGIN/scripts/deep-loop stop <名前>
```

作業ディレクトリは `~/.local/state/deep-loop/<名前>` にできる。
runner はこの機械で `claude -p` を起こすので、実行する機械（サーバー）の上の Claude Code から使う。

## 始める

1. **brief を固める。**
   作業役は brief を上限として扱い、書かれていない要求を足さない。範囲が曖昧だと課題も散らばる。
   依頼から次の見出しを埋めた brief の草案を作る。

   ```markdown
   # <題名>
   ## Deliverable
   design | refactor | bugs | research（混ざるなら複数）
   ## Goal
   <答えてほしいこと、設計してほしいもの、洗い出したいもの>
   ## Scope
   <対象と、対象外>
   ## Requirements and constraints
   <満たすべきこと、変えてはいけないこと、前提>
   ## Repositories
   <サーバー上の絶対パス。読むだけで変更しない>
   ## Sources
   <優先してほしい情報源。無ければ省く>
   ## Language
   <成果物の言語。既定は日本語>
   ```

   要求と制約はワクさんの言葉から取る。skill が補ったものは、補ったと分かる形で見せて確かめる。
   範囲を大きく変える項目が埋まらないときだけ、会話で確かめる。埋められない細部は推測で足さずに外す。
   リポジトリの絶対パスは、実在するかを `ls` で確かめる。
2. **名前とラウンド数と開始時刻を決める。**
   名前は英小文字・数字・ハイフン（例: `auth-redesign`）で、`status` の一覧と重ならないものにする。
   ラウンドは既定の 3（上限も 3）。開始時刻は、夜間に回すなら `--at` で指定する。
3. **始める前に確認を取る。**
   brief、名前、ラウンド数、開始時刻を見せ、始めてよいかを聞く。
   1 ラウンドで作業役を課題の数だけ起こし、課題ごとに反証役も起こすので、数十エージェントになりうる。
   費用の目安は、ファイル 3 つほどの範囲で 2 ラウンドを回して約 18 USD（試走の実測）。課題の本数に比例して増える。
   内訳は Opus の反証役が約 4 割、Sonnet の作業役が約 1/4 で、残りが最終の書き手、integrator、planner である。
   費用を抑えたいと言われたら、`--model verifier=sonnet` を付けると反証役も Sonnet になる（精度の関門が弱くなることも伝える）。
   確認なしに始めない。
4. brief を標準入力で runner に渡して始める（`--repo` は brief のリポジトリごとに付ける）。
5. 始めたことと、進み具合の見方（この skill に「進み具合は？」と聞けばよい）を伝える。

## 進み具合と成果物

- **進み具合**：`status <名前>` の出力から、走行中か、何ラウンド終えたか、各ラウンドの進展と未解決の問いの数、反証の結果を 2〜3 行で伝える。
  反証で否定された知見が多いなら、作業役の結論に誤りが混ざっていた信号なので、そのことも伝える。
- **成果物**：`report <名前>` の出力をスクラッチパッドに保存して読み、結論と未解決の問いを短く伝える。全文を会話に貼らない。
  手元に置きたいと言われたら、指定された場所に書き出す。
- **再開**：止まった作業を続けるときは `resume <名前>`。完了したラウンドの続きから始める。
  未解決の問いに人が答えられるなら、その答えを `brief.md` の末尾に「## Answers」として書き足してから再開すると、それを前提に続きを回せる。
  始めるときと同じく、再開の前に確認を取る。

## 失敗したとき

- `status` の終了コードが 0 でなければ、`~/.local/state/deep-loop/<名前>/session.log` の末尾を見て原因を伝える。
- 成果物が無いまま止まっていれば、`journal.jsonl` の最後の行が理由（計画の終了、失敗、進展なし）を持っている。

## しないこと

- 作業ディレクトリのファイルを手で書き換えない（brief への答えの追記は、ワクさんに頼まれたときだけ）。
- 走っている作業を勝手に止めない。止めたいと言われたら `stop <名前>` を打つ。
